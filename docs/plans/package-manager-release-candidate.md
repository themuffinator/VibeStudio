# Package manager release-candidate acceptance

Objective: achieve a release-candidate, professional-grade package manager for
VibeStudio's supported folder, PAK, Doom/texture WAD, ZIP, and PK3 workflows.
This is a completion audit, not a list of optional follow-ups. The goal remains
active until each requirement has current evidence or an explicitly accepted
product boundary. A passing subset of tests is progress, not release readiness.

- Record the tested source state, command, platform and result. Do not substitute

## Managed temporary-copy ownership and retained-session review (2026-10-05)

`core/package_copy_store` registers each studio window's copy session under the
resolved OS temporary root's `vibestudio-package-copies/<uuid>.copies`. The
session writes a small atomic version-1 record and owns a native directory lease
through the existing `PackageDraftAccess` service. A returned batch-directory
lease also retains the session, preventing premature cleanup when consumers
keep only that lease. The shell creates/adopts its managed session on the copy
worker. Code and Level temporary-path guards continue to use the same session
root. Per-window initial reservations are unchanged.

Last-owner release queues bounded explicit cleanup on a dedicated pool while
retaining native ownership. Application exit drains that pool after the shell
and ordinary workers release their references. Abrupt process termination
releases native ownership and leaves files for review; there are no stale lock
files to release. Missing/interrupted or invalid session records retain explicit
diagnostics, but recognized safe layouts can still produce a review token.
Unregistered older `vibestudio-copies-*` directories are neither adopted nor
removed. No real retained user store was cleaned during this work.

File > Temporary Package Copies > Review Retained Copies exposes bounded actual
payload size, file/batch counts, creation time, full IDs/paths, ownership
availability, storage fingerprints and errors. It runs inspection/deletion on
owned workers, polls bounded progress state on the UI thread, and keeps
Cancel/Close outside its scrolling content. Close requests cancellation and
waits. Metadata rechecks and fingerprint preparation also honor cancellation.
Reduced motion uses static initial progress; explicit file cleanup reports a
determinate total. Unused-session deletion confirms its identity and size,
defaults to Cancel and warns that consumer edits may be present. Native owner
exclusion and the selected fingerprint are checked again on the worker.

ownership; inspection and dry runs create neither files nor preferences. Future
settings block written discard; legacy settings remain byte-for-byte unchanged.
Unknown/repeated/conflicting/malformed options fail with exit 2, review/ownership
or cleanup failures use exit 1, and successful inspection/discard uses exit 0.

payload contents. Review admits 128 sessions, 250,000 aggregate entries, depth

entries and unknown session-root names prevent cleanup. Explicit retained-session
cleanup removes individual reviewed files and empty directories, with the record
last; cancellation or failed deletion may leave a partial tree for fresh review.

## Durable shared temporary-copy reservations (2026-10-05)

Managed copies now reserve initial bytes, files, entries and one batch against
both their window budget and the physical store's shared policy before creating
payloads. Defaults are 8 GiB, 32,000 files, 160,000 entries and 256 batches.
The shared hard entry ceiling is 248,832, leaving review capacity for session
records and batch roots. Implied parent folders count before payload reads;
managed path-depth admission also leaves room for the batch directory.

The existing native `PackageDraftAccess` adapter coordinates store mutations
through a separate `.coordination` directory. This permits Windows session/root
enumeration while the coordinator has exclusive maintenance ownership. Session
creation, policy changes, reservation updates and normal/explicit cleanup share
that coordinator. Acquisition retries honor cancellation and stop after two
seconds. Native process exit releases ownership without a stale lock file.
Version-2 session records contain checksummed counters, including pending and
failed-cleanup state, committed atomically with `QSaveFile`. A pending reservation
survives process termination even if no payload was written. Verified failed/
cancelled batch cleanup releases it; completed or failed-cleanup reservations
remain until session removal. Failed metadata updates preserve prior charges.

The policy lives in the store's `limits.json`, independent of QSettings overrides.
Review Retained Copies now distinguishes actual logical file size from shared
initial reservations and shows each session's recorded charges. Shared Storage
Limits edits the four caps on a worker using the reviewed policy checksum.
Concurrent changes require refresh; lower caps preserve existing copies.

## Bounded archive indexes and streamed ZIP directories (2026-10-05)

Each on-disk archive/folder load now has shared GUI/CLI admission ceilings:
250,000 physical records including skipped entries and implied folders, 128 path
components, 64 MiB of logical index metadata and 64 MiB of retained chunk hashes.
The core API permits stricter limits and rejects values above the ceilings.
Metadata charges encoded directory records, decoded paths, warnings and entry
notes; folder source identity paths also count. These are logical accounting
bounds, not exact heap/working-set quotas. Folder hashes share one budget across
all files, including per-file 64 KiB chunk rounding. Fingerprint admission checks
the source size before hashing it. Other direct fingerprint callers keep their
existing default policy unless they pass the new optional cap.

ZIP central directories stream one bounded record at a time, including records
whose names/extra fields/comments cross chunk boundaries. A separate verified
device retains the central stream's 64 KiB cache while the payload device checks
local headers, avoiding alternating cache eviction for every entry. Physical
record counts and encoded metadata are admitted before directory accumulation.
Every skipped branch advances the streamed directory offset. PAK/WAD loops,
folder enumeration, implied-folder expansion and duplicate preparation check
cancellation; indexing progress is reported every 64 records, followed by an
index-preparation phase. Sorting remains bounded and checks cancellation before
and after the sort, without interrupting the sort itself.

Failure clears the unpublished reader, identities, entries and warnings. The GUI
worker returns no adoptable archive/staging result; CLI info/list/validate return

## Aggregate package sessions and asset-folder admission (2026-10-05)

`PackageArchiveSession` now shares the on-disk index ceilings across its whole
stack: 250,000 physical/skipped/implied records, 64 MiB of logical metadata and
64 MiB of chunk fingerprints, with at most 64 layers. Empty bookkeeping layers
also count. Hidden overrides retain their source charges. Layer labels/paths,
newly relocated entry paths, warning prefixes and mount-prefix folders consume
the shared allowance. Prefix folders are conservatively reserved per layer so
removing an override cannot reveal uncharged directories. Relocated paths obey
the 128-component ceiling and existing 4,096-character reader limit. These are
logical admission limits, not exact heap or process memory quotas.

Before loading a new source, the session reserves its layer metadata and passes
the remaining entries/metadata/fingerprint allowance to `PackageArchive::load`.
The fingerprint cap therefore applies before hashing that source. Projection
and merged-index checks happen in a candidate session; failure or cancellation
preserves the previous layers, usage and lookup ownership. Pop/clear release
the corresponding charges. Merging checks cancellation and reports its phase;
sorting remains bounded and checks cancellation around the sort. A duplicate
path within one layer now keeps the first physical record's metadata, matching
the owning reader's bytes. Later layers still override earlier layers. Warning
severity (`blocksSaving`) survives merging.

by `auditLevelMapTexturesInDirectories` and CLI `map textures`. It now uses the
